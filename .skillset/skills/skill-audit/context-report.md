# Context report contract

Use `skill-audit.context/v1`, defined by [context.schema.json](context.schema.json). Write one JSON report per context reviewer and provide its actual path; `audit/context.json` is the single-reviewer default. When file tools are unavailable, return the complete JSON inline. [context.example.json](context.example.json) shows a minimal incomplete investigation.

## Evidence before recommendations

Keep collector output unchanged and reference it in `sources`. Sources may be files, native catalogs, APIs, UI observations, memories, conversations, or user-supplied records. No filesystem collector or provider-specific service is required. Each source has a stable report-local ID, locator, observation date, optional SHA-256, and coverage description. Use null when a date or hash is unavailable. For filtered snapshots, `parent_id` identifies the original source; never present a parent fingerprint as the filtered file's fingerprint. Register both sources.

`scope` lists every assigned candidate ID and the boundary of the investigation. IDs identify candidates, not names alone: two same-name skills remain distinct, and a broken alias can be a candidate without a readable body. Preserve identity from the supplied inventory or assign explicit IDs when none exist. Assign disjoint candidate sets across context reviewers. The coordinator checks that their combined coverage contains each assigned candidate exactly once; qualify claim and source references by report when IDs repeat across reports. Each candidate gets exactly one record with its known locations, coverage status, claims, and unresolved questions. `complete` means all six context areas were addressed, including explicit gaps; it does not mean every answer is known. Use `partial` or `blocked` when an area was not investigated or access prevented inspection.

Claims use an `area`: purpose, provenance, resources, consumers, usage, or history. Their `basis` is observed or inferred, and every claim cites at least one source with a precise `locator` (line range, record ID, timestamp, or comparable anchor). Keep evidence, interpretation, and uncertainty distinct. A source's assertion about authorship or purpose is an observed assertion, not independently verified truth. Record missing answers in `questions`, with the relevant area and the next evidence that could answer them. Cover each area with a claim or question; a gap is valid and does not require broad searching.

Usage claims also include `metric` with its definition, measurement window, and coverage. Distinguish installed, enabled, advertised, read, invoked, and useful. If no usage evidence exists, record a usage question rather than an invented zero. File age never supplies last-use evidence. A directory comparison must state whether it covers SKILL.md alone or the supporting resources too.

The context report contains no keep/update/consolidate/disable/retire verdicts. The coordinator uses its claims and gaps to make recommendations in the audit's requested format. Keep original reviewer reports intact; preserve any coordinator corrections separately by candidate/claim ID, replacement interpretation, and reason.

## Run history and checks

`run` records reviewer, model and effort when exposed, and condition (ordinary audit or an explicitly described experiment). Record searched sources and failed or unavailable searches in `searches`, including their source locator, observation date (null if unavailable), scope, outcome, and reason. Sources are evidence actually inspected; searches describe attempted discovery. Disclose exposure to held-out conclusions in `limitations` for experiments. Prior notes remain legitimate evidence in ordinary audits.

Before handoff, check JSON against the schema using an available Draft 2020-12 validator, or explicitly disclose that schema validation was unavailable. Then check these relationships: unique source/candidate/claim IDs; each assigned candidate appears exactly once; all source, parent, and evidence IDs resolve; each context area is covered; usage claims have metric details; and cited anchors support their claims. Preserve source snapshots when tools allow. If a cited file changed, recheck its claims rather than merely refreshing the hash. These relationship and evidence checks are reviewer/coordinator responsibilities in this prototype; JSON Schema does not enforce them all. A structurally valid report does not establish sound judgment.

Markdown is optional. Group it by candidate, presenting established context, inferences, and open questions; then list collection gaps. Preserve complete claims and sources in JSON even when the conversational summary is short. This contract requires no bundled scripts or services.
