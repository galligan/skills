# Prototype trial output

Use [context-report.md](context-report.md) for the context stage. The coordinator writes a separate trial assessment, preserving the context report and identifying its source snapshot. Write assessment JSON with `run`, `reviewer`, `coverage`, `recommendations`, `rejected_candidates`, `context_reports`, and `limits`. `context_reports` lists each input context report by stable ID, locator, schema version, and SHA-256 (null when unavailable, with the limitation recorded). Qualify references to context candidates and claims with that report ID. `run` records the model, exposed effort setting, trial condition, collector version, and supplied evidence snapshot (use unknown when unavailable). `coverage` contains every assigned candidate with a disposition and reason. Each recommendation contains `target`, `action`, `evidence`, `reason`, `uncertainty`, `change_owner`, `verification`, and `rollback`. Allowed actions: keep, update, consolidate, narrow_scope, disable, retire, investigate. Evidence uses stable identifiers from inventory records, supplied documents, or structured native sources and retains the source date, metric definition, measurement window, and coverage when applicable. Do not fabricate usage or author identity.

Evaluate whether the reviewer distinguishes aliases from copies, keeps external entries eligible, preserves a customized fork, reports broken links, and refuses to infer non-use from age. The coordinator records corrections and rejected candidates with reasons. Compare runs only when their assigned candidates, evidence snapshot, and evaluation ground truth are held constant; valid JSON alone is not success.
