# Publishing skills and plugins

The canonical source is `.skillset/plugins/mg-skills/skills/<name>/`. Provider plugin bundles and marketplace indexes are generated by the pinned Skillset compiler. There is no second hand-maintained root `skills/` tree.

## Current individual-skill route

The skills CLI recognizes conventional skill roots, Claude marketplace entries, and a recursive fallback. It does not require a repository-root `skills/` directory.

This repository declares the catalog explicitly in root `skillset.yaml`:

```yaml
marketplaces:
  galligan:
    title: Matt Galligan
    description: Shareable agent skills by Matt Galligan.
    targets: [claude, cursor]
    plugins:
      - plugin: mg-skills
```

With Skillset 0.26.1, ordinary `bun run build` renders the local catalogs. The Claude catalog points to `./plugins/mg-skills/claude` and omits `metadata.pluginRoot`. The skills CLI consequently discovers the generated Claude skills before recursive fallback.

After publication, `npx skills add galligan/skills --skill <name>` selects an individual rendered skill. A supported explicit-path alternative is `npx skills add galligan/skills/plugins/mg-skills/claude/skills/<name>`.

This is an individual-skill installation. The CLI does not install the plugin's hooks, MCP configuration, commands, agents, or plugin dependencies. It copies the selected skill directory. All required references, scripts, assets, and license files must travel inside that directory.

Every skills-CLI agent selection receives the selected Claude rendering. Keep the initially published skills portable; target-specific prompt syntax, enforcement, or plugin services need a separate installation contract. Review those requirements before listing a skill for individual installation.

## Compatibility evidence

Verified September 12, 2026 with actual `@skillset/cli@0.26.1` generation and `skills@1.5.26` (upstream commit `d667282815248da03a08a18272b5d2eef9caf77c`). Disposable fixtures used an adaptive partial and a plugin-shared reference so raw source and generated output could be distinguished.

| Fixture | Repository-root individual installation result |
| --- | --- |
| Explicit catalog, matching this repository | Expanded partial, generated `LICENSE.txt`, and copied `references/guide.txt` |
| Implicit default catalog | Raw source retained the partial directive and `resources:` field; generated license and reference were missing |
| Implicit catalog with only redundant `pluginRoot` removed in the fixture | Rendered payload and resources restored |

The tests performed actual local copy installs into disposable workspaces with an isolated home. They did not install into user agent configuration. They prove the current generated layout and copy behavior, not a hosted installation of this still-empty repository or runtime behavior of future skills.

The implicit catalog emits `metadata.pluginRoot: ./plugins` alongside `source: ./plugins/mg-skills/claude`. The skills CLI combines both paths. Claude's documented behavior instead ignores `pluginRoot` for `./` sources. Retain the explicit source path; shortening it to accommodate the skills CLI would change Claude's resolution.

Do not rely on recursive discovery or its first-name-wins deduplication. `--full-depth` is deliberate recursive discovery and can expose unique source-only skills even when a default catalog works. Do not treat `--list --skill <name>` as a selection test: listing happens before skill filtering in the pinned CLI.

## Skillset follow-up

- [SET-528: Align implicit marketplace discovery with npx skills](https://linear.app/outfitter/issue/SET-528/align-implicit-marketplace-discovery-with-npx-skills) covers implicit/explicit catalog parity and pinned consumer conformance.
- [SET-529: Support portable individual-skill publishing from plugin-owned source](https://linear.app/outfitter/issue/SET-529/support-portable-individual-skill-publishing-from-plugin-owned-source) covers a standards-only generated collection, resource closure, collisions, and the required output-topology decision.
- [SET-402](https://linear.app/outfitter/issue/SET-402/agent-skills-baseline-renderer-at-agentsskills-with-codex-coalescing) owns the planned standards baseline renderer. Its current design does not independently export plugin-owned skills to root `skills/`.

A future generated `skills/<name>/` collection may be the cleanest public surface. It remains a proposal until Skillset implements the contract; this repository does not add a copy script or call provider output neutral.
